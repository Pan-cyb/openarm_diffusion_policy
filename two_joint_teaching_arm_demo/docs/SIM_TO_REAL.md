# 从 MuJoCo 到单片机和双电机 CAN

## 1. 数据边界

仿真和实机必须先约定统一的关节语义：

```text
q[0] = shoulder，单位 rad，正方向按模型右手定则
q[1] = elbow，单位 rad，正方向按模型右手定则
dq   = rad/s
tau  = N·m
```

MuJoCo 中 `data.ctrl[0:2]` 是目标关节角。实机上位机也只发送相同语义的目标，
不直接发送未经限制的电流或力矩。

## 2. 推荐架构

```text
PC
  MuJoCo / 示教轨迹 / 日志
        |
        | USB CDC、UART 或以太网
        | ARM / TARGET / DISARM + CRC + sequence
        v
MCU 主控
  安全状态机
  关节限位
  目标速度限制
  PC 看门狗
  CAN 反馈看门狗
        |
        | CAN-FD 或经典 CAN，取决于电机固件
        v
DM4310 #1                 DM4310 #2
send 0x01 / recv 0x11     send 0x02 / recv 0x12
```

OpenArm 当前文档使用不同的 Send ID 和 Receive ID，并要求同一总线上的 ID
唯一。这里的 `0x01/0x11`、`0x02/0x12` 是教学配置，烧录前必须通过厂商工具和
实际电机配置核对。

## 3. MCU 状态机

```text
BOOT
  -> DISABLED
  -> ARMED
  -> RUNNING

任意状态
  --急停/欠压/过温/CAN 超时/PC 超时-->
  FAULT
```

关键规则：

- 上电不使能电机。
- 清故障不等于自动使能。
- `ARM` 前确认急停释放、反馈正常、关节在允许范围内。
- `TARGET` 必须带递增序号和 CRC。
- 超过 100 ms 没有 PC 指令时停止发送运动目标并禁用电机。
- 超过约定周期没有任一电机反馈时进入故障。
- MCU 对目标做位置限位、速度限制和突变限制。
- 上位机断开、程序崩溃或 USB 拔出都不能让电机保持无限期运动。

## 4. 达妙 CAN 适配层

OpenArm 的 CAN 工具使用达妙 MIT 控制模式，并在总线上区分 Send ID 与 Receive
ID。实际协议还涉及：

- 电机使能、禁用和清故障帧。
- 位置、速度、`Kp`、`Kd`、转矩的量化范围。
- 不同控制模式的命令 ID。
- 反馈中的位置、速度、力矩、温度和错误码。
- CAN 与 CAN-FD 的 DLC 和比特率。

这些字段必须从手头 DM4310 的对应固件手册或官方 OpenArm CAN 库生成，不能只凭
网上示例猜测。本项目的 `dm4310_adapter.h` 因此只定义接口，不提供可上电的字节
打包实现。

## 5. 从仿真迁移到实物

1. **确认机械结构**：测量两个关节轴、连杆长度、质量和重心。
2. **核对电机**：记录具体型号、减速比、固件、CAN/CAN-FD 模式和 ID。
3. **只读通信**：先只接收两个电机状态，不发送使能或运动命令。
4. **确定零位**：建立编码器原点到 MuJoCo `q=0` 的偏置和正负方向。
5. **单电机空载**：低电流、低速度、小角度，分别验证方向、限位和急停。
6. **单关节带机构**：确认重力方向、摩擦和减速比。
7. **双关节低速**：先用固定目标，再回放短轨迹。
8. **记录差异**：比较实机与 MuJoCo 的 `q/dq`，再辨识摩擦、阻尼和延迟。
9. **更新模型**：只用实测证据修改质量、惯量、摩擦和执行器响应。
10. **最后接策略**：策略只输出目标，MCU 安全层始终保留最终否决权。

## 6. 不应直接照搬的内容

- MuJoCo 的 `kp=30`、`kv=1.5` 是仿真位置执行器参数，不等于电机固件的 MIT
  `Kp/Kd` 原始数值或量化字段。
- MuJoCo 的 `forcerange=±7 N·m` 是仿真限幅，不代表持续允许峰值运行。
- 仿真零位、实物机械零位和编码器零位通常不是同一个概念。
- 仿真没有自动包含真实 CAN 延迟、丢包、温升、供电压降和结构柔性。
