# 双臂抽屉放方块：示范采集方案

日期：2026-11-16。本文是实验设计建议，不代表已经采集数据或完成任务验收。
具体按键、启动/对齐排除和落盘步骤见 `数据采集操作流程.md`。

## 能不能用 Diffusion Policy

可以作为 DP 的目标任务：根据多视角图像和双臂本体状态，预测两只手协同的
后续动作序列。DP 的 IJRR 扩展版已经包含双臂、多阶段实机任务，但这不是
“任意长任务一定能成功”的保证。本任务还取决于抽屉阻力、夹爪抓取可靠性、
可达性、两臂避免相撞、相机可见性，以及示范与观测/动作时序的质量。

第一轮先做一个明确的单任务策略，不必先上 VLA 或复杂任务规划：

```text
初始：抽屉关闭；方块在桌面；两臂在已验收的可重复起始姿态
1. 左手靠近并抓住把手
2. 左手拉开抽屉，按一致策略保持或释放
3. 右手抓起方块
4. 右手将方块放入抽屉、松开夹爪并离开
成功：方块完全进入抽屉并稳定，右手未再夹住它
```

用户任务没有要求关抽屉，不擅自把“再关上抽屉”加到成功条件。
若抽屉会回弹，第一轮统一采用左手保持开启、右手放入后离开的策略；
若不会回弹，也应先统一策略，避免同一视觉状态下示范行为无谓地摇摆。
整段示范作为一个 episode 保存，不把各阶段分别采完后拼成虚假的连续操作。
可另外记录阶段标签用于失败分析，但普通单任务 DP 不要求逐帧框选目标或手写奖励。

## 一条示范具体记录什么

不是只拍三段视频。当前接入以官方 OpenArm Dataset v0.4.0 为原始格式：

| 项目 | 内容 |
| --- | --- |
| 图像 | chest、wrist_left、wrist_right，独立源时间戳 |
| 实际状态 | 左右臂实际关节位置及夹爪状态；驱动若输出 qvel/qtorque 也原样保留 |
| 控制目标 | WebXR 经 IK 得到的左右关节目标及夹爪目标，不把原始手柄位姿直接当目标关节 |
| 语义 | 任务 prompt、episode 编号、success/fail、初始布局/异常的人工备注 |
| 可追溯性 | 相机端口映射、编码模式、名义帧率、源/接收/发布时钟元数据与软件配置 |

若两臂各为 7 个关节加 1 个夹爪通道，初始关节空间基线合计为 16 维动作。
原始数据仍按左右两路分别保存，训练适配时明确拼接顺序和单位。
不要把左右夹爪未经定义地都解释为同一个 0..1 值；保留驱动原始语义。
真实反馈与控制目标是不同信号，不用反馈简单冒充“同一时刻应执行的动作”。
电机回报扭矩也不能未经验证就等同于末端接触力。

胸部视角应能观察抽屉/把手、方块和放置结果；腕部视角要覆盖接近与夹取细节。
采集时和自主运行时必须保留相同的可用视角。
当前用户确认大疆安装在机器人胸前，不是操作者胸前；实际工作区覆盖仍待画面检查。
第一轮优先固定相机相对机器人/工作区的安装，不增加额外视角变化。

## 腕部图像方向规定

两路腕部相机统一旋转 180 度，上下和左右同时反转；不是仅上下翻转（`vflip`），
也不对胸部或后续全局相机自动应用。详见 `../AGENTS.md` 的相机图像方向规则。
预览、训练和部署必须保持一致，记录变换版本与应用位置，避免重复翻转或覆盖原图。
2026-11-16 已在独立 FFmpeg 样图和 FFplay 单路预览中通过 `hflip,vflip` 实现旋转，
用户初步认可展开后的视野。后续软件已在三相机服务入缓存前接入一次
`rot180-v1`，合成图测试通过；训练转换不应再次旋转，部署链路仍未接入验收。
旧原始单帧与旋转预览不能混称为已统一处理的数据集。代表性图像见
`evidence/2026-11-16-camera-preview/README.md`，还需检查任务接触阶段的目标可见性。

## 外部全局视角计划

用户计划再购两台微雪，尚未确认下单、到货和镜头型号，也未确定最终模型使用几路图像。
胸部、双腕与外部相机的职责以可见性互补为准，不以“相机越多越好”为验收标准。
外部机位可从工作区侧上方、约 45 度向下试摆；角度仅为建议，不是论文固定要求。
优先检查把手、方块初始区域、抽屉完全打开后的内部与释放结果；不要求腕部图像
在每帧都覆盖整个任务。固定机位和预处理后，再测试所有相机同时运行的 USB 负载。

## 如何遥操一条示范

1. 先在录制外复位抽屉和方块，检查两臂起始姿态、视野与安全范围。
2. 三相机已预热、取流健康，且双臂遥操和停止机制已现场验收后，再开始 episode。
3. 用 Quest 平稳完成整段任务。允许正常的小调整，不刻意抢速度或加很多空等。
4. 放置完成、夹爪释放，短暂保持清楚可见的成功状态，再结束并标成功。
5. 复位和长时间等待不要录进下一条示范；不要把复位轨迹伪装为任务动作。
6. 失败、掉帧、碰撞风险、失去抓取等要标失败并保留诊断，不混入成功示范主集。

第一轮成功示范优先选择连贯、任务确实完成的轨迹。自然的小修正可以保留；
抓取反复失败、长时间乱试或人工伸手介入的轨迹单独标记，不能标为无干预成功。
普通成功行为克隆基线不默认用所有失败轨迹训练；失败记录用于定位薄弱阶段和补采。

软件接入不等于真机安全验收已完成。现有记录中左臂对齐、修改后的 VR 安全按键、
Neutral Capture、队列丢弃等仍有待验收项；必须先补齐，不能直接拿抽屉做首次验收。
软件停止不等于硬件急停；抽屉拉力和双臂接近尤其不能靠“模型会自己避碰”兜底。

## 是否每次改变位置

不需要每条都移动抽屉柜体，也不建议第一天同时随机所有东西。
先定义“部署时希望适应哪些变化”，训练示范覆盖这个范围，而不是盲目求多样。

第一阶段建议固定抽屉柜体、相机、方块种类、光照和初始关闭程度；
方块先用一个容易的位置采少量管线验证，再在安全可达的小区域选若干位置重复。
初始位置顺序打散，避免“前半段全左边、后半段全右边”造成批次偏差。

例如首批 100 条可以考虑约 10 个方块初始位置、每个约 10 条成功重复。
这是便于执行的工程设计示例，不是 DP 的通用最佳配方。
位置也可以连续小范围随机，不需要真的标成机械网格，但要记录覆盖区域。

当固定柜体基线有效后，再逐项扩展：

- 方块的位置、朝向、抓取姿态。
- 抽屉初始开合程度（如果部署时确实可能不是完全关闭）。
- 柜体在工作区内的少量平移/朝向变化（只限已确认两臂可达且安全的范围）。
- 光照、背景、方块外观等部署确实需要的变化。

每次最好只增加少数变化，才能判断失败来自哪里。
只固定一个布局反复录很多遍，不能当成已验证能泛化到任意摆放。
相机/机器人基座/物体的关系变化应明确记录，不能靠训练默认消除。

## 先采多少条

没有保证成功的固定条数。下列是本项目的建议分期，不是论文承诺：

| 阶段 | 成功完整示范量 | 用途 |
| --- | --- | --- |
| 试录 | 5–10 条 | 检查图像、状态/动作、夹爪语义、时间戳、任务边界 |
| 第一轮训练 | 累计 50–100 条，建议先以 100 为目标 | 固定柜体、小范围方块变化的基线 |
| 扩展和补采 | 视失败分析逐步累计约 200–300 条 | 扩大部署范围并补足失败布局/阶段 |

不是采够 100 或 300 条就结束：训练后用独立初始条件评估，分别记
“能拉开”“能抓住”“能放入”和“全流程成功”，对薄弱阶段/布局补采。
若遥操本身不能高比例成功，先改善任务或控制，不应直接靠堆示范量补救。

论文的不同双臂任务分别使用过 162、210、284 条示范，且成功率仍不同，
这只能说明数量具有任务依赖性，不能把其中一个数字套成当前任务的保证。
测试布局应独立保留；训练/验证按完整 episode（最好再按布局/采集批次）划分，
不要把一条轨迹相邻帧分进训练和验证后宣称泛化良好。

正式自主评估需要另外授权，并保持限速、工作区约束与人工可中断的条件。
训练 loss 下降或离线动作误差小，不等于抽屉任务实机成功。

## 时间戳与后续训练

当前接入保存原始流和时钟说明；每路 30 fps 不等于同步曝光。
胸部为 V4L2 PTS 映射到主机 Unix 时间，腕部为主机收到帧的时间，
它们的延迟含义不同。`camera_timing/episode_*.jsonl` 保留源、接收、发布信息，
但不是曝光时间标定结果。

先做实机流稳定性和可见事件时间检查，再选择 20/30 Hz 等训练采样率，
形成历史观测与后续动作窗口；不要按“第 N 帧”硬拼三路，也不要用补帧掩盖断流。
目前没有完成端到端时延校准或同步曝光验收。

同一批合格的原始示范可以供 DP 和后续 VLA 分别适配，提前保存任务语言，
但不同模型的相机映射、动作表示、归一化和数据版本仍要单独配置。
原始数据与时钟/布局备注应保留，不只保留转换后的训练文件。
