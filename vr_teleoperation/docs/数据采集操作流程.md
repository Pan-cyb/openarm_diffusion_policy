参数说明见 `../local/four_camera/README.md`，当前结果以 `PROJECT_STATUS.md` 顶部为准。

更新：2026-11-21，Asia/Shanghai。适用双臂 pedestal、Quest WebXR 和本地四相机采集入口。
本文完成软件流程设计，不是本次启动相机、CAN 或机械臂的授权。

图像先写临时文件再原子发布，结束时同步本条数据、目录和时钟记录，
原子提交 metadata 后再回传保存确认。Expansion 当前经 USB2 连接，
约 30 秒条目的保存曾需约 17–23 秒；CLOSING 时等待，不要抢先复位或开始下一条。

## 先记住这一条

**启动设备 → 进入 VR → 必要的中立位标定 → 双臂对齐 → 任务起始布置 →
X 开始 → 等 RECORDING → 做任务 → X 成功结束 → 等 Saved → 录制外复位。**

页面 Start、终端 START、手柄 A 都不是“开始采数据”。
不要录启动、初始对齐、长时间等待和人工复位；任务本身的接近、抓握和放置需要完整录入。

## 按键与状态

| 操作 | 含义 | 是否录制 |
| --- | --- | --- |
| Quest 网页 Start | 进入沉浸式 WebXR | 否 |
| 终端 START | 授权官方数据流启动/使能双臂，会移动 | 否 |
| A 长按 1.5 秒 | 机械臂重新 Start，会初始化，随后需重新对齐 | 否；打断正在录的条时记失败 |
| Y 长按 2 秒 | Home Neutral，中立手位映射到模型 home | 不是录制；仅在官方起始姿态、STARTED 时按既有手册使用 |
| Trigger | STARTED 时许可初始对齐；对齐后控制夹爪 | 对齐过程必须在录制外 |
| X 单按 | READY 时开始一条；RECORDING 时结束并请求标成功 | 是，起止边界独立于 Arm Start |
| B 单按 | 优先发 Arm Stop、冻结手部输出；当前条请求标失败 | 结束当前条，不自动标成功 |
| Grip | 当前无任务功能 | 不使用 |

正常成功结束推荐再次按 X，不用 B。原因不是 B 不能结束录像，而是它保留了
安全停止职责；一次掉物、方向错误或紧急中断不应被顺手标成成功。
**X 成功结束不关电机、不自动回 home、不自动复位场景。**
**B 不是硬件急停：它调用既有官方 Stop；disable/断电后无抱闸机械臂可能下落。**

HUD 的 REC 行才是本地采集流程的确认：

| 状态 | 下一步 |
| --- | --- |
| DISABLED | 当前不是采集入口；X 不工作 |
| IDLE，且 READY | 可按 X 开始；若不 READY，查看阻止原因 |
| STARTING | 开始命令已接受，等 Recorder 确认；先保持起始姿态 |
| RECORDING，含编号和秒数 | 正式做任务 |
| CLOSING | 保存/核对尾帧；不要开始下一条或复位 |
| IDLE，Saved: success/fail | 本条结束；确认结果后在录制外复位 |
| UNKNOWN | 状态连接不可用，不猜测录制是否成功；查看电脑和日志 |

桌面官方页面仍保留原有 Collecting 显示和操作按钮；它在 CLOSING 时可能已显示
非录制，但开始请求仍会被服务器拒绝。以 HUD 或 `8000/capture/status` 的
Recorder 确认结果为准，不能只看桌面 Collecting 消失。

## 8080 固定入口

仍然打开 `http://localhost:8080/`，不再手写日期、“1015”或 `?v=...`。
服务端把裸入口和旧 query 都跳到 `/ui/<前端内容哈希>/index.html`，
所有相对 JS 模块都在同一个版本目录下；响应带 `no-store` 和版本头。
网页进入 VR 前会显示 `OpenArm UI <哈希>`，`/ui-version` 可核对服务端版本。

这次没有找到名为“1015”的独立页面文件；旧实现使用 `20261115-compact3`
query 规避缓存。现在不是换一个 query，而是统一默认入口。
修改软件后必须重启相应 WebXR 服务，已经打开的沉浸会话不会热更新。
如 Quest 仍显示旧 HUD，先退出旧沉浸会话，重新加载裸入口并核对版本；
若仍命中旧网页缓存，只清除此 localhost 站点缓存后重开，不清空整个浏览器数据。
头显端最终显示、按键和真实控制仍待现场验收。

## 未来现场启动

常用启动脚本现在默认进入四路采集，不再进入旧遥操流：

```bash
cd /home/pan/openarm_diffusion_policy/vr_teleoperation/local
bash run_webxr_real_pedestal.sh
```

启动后自动检查数据盘、四路相机和基本画面，只输入一次 `START`，
同时确认网络/CAN 准备及机械臂启动，不再询问 `CAMERAS`、`ROBOT`、姓名或地点。
操作者默认记当前登录用户名，地点如实记 `unspecified`；需要时可用
`--operator`、`--location` 参数覆盖，不编造现场信息。
不会因修改脚本自动替换已运行的会话；
已运行旧遥操流时，先按既有安全停机流程退出，再执行同一命令。

也可显式传参数；下面只是操作说明，本次没有执行真实入口：

```bash
cd /home/pan/openarm_diffusion_policy
PY=vr_teleoperation/upstream/dora-openarm-data-collection/.venv/bin/python
"$PY" vr_teleoperation/local/four_camera/launch.py \
  --mode real --allow-cameras --allow-robot \
  --operator 操作者姓名 --location 现场位置 --max-seconds 3600
```

真实模式默认写 Expansion 的 `drawer_block/raw`，自动生成 `real_年月日_时分秒` 会话目录。
每次运行用新会话，拒绝含糊续写或覆盖旧集。也可显式传 `--name`；
自定义 `--directory` 必须仍在同一块已核实的 Expansion 文件系统上。
`--max-seconds 3600` 是包含预热和等待确认在内的一小时相机会话上限，
不是单条录制时长；接近上限时应结束当前条并退出，不自动续开。

1. 入口检查相机配置、操作者/位置、输出盘身份及至少 10 GiB 可用空间。
2. `--allow-cameras` 明确允许打开四路相机；按系统提示授权相机辅助程序，等待预热。
3. 相机就绪后输入一次 `START`，确认网络/CAN 准备与随后机械臂启动。
4. 检查通过后运行机械臂数据流，不再二次询问；官方 UI 会自动 Arm Start，**会有运动**。
5. Quest 加载裸 8080 地址，点网页 Start；不要因此再无必要地长按 A。
6. 必要时先做 Y Home Neutral，再按既有手册重新 Start；仍在录制外完成。
7. 分别 Trigger 对齐右、左臂，确认两边都为 ALIGNED。
8. 在录制外就位到可重复的任务初始状态，松开不需要按的按钮，等待 READY。

四相机入口是当前采集入口。不要直接运行实机 YAML 绕过权限门。
`run_webxr_real_pedestal.sh` 默认转入该入口；相机启动器完成检查后以
`OPENARM_REAL_DATAFLOW` 回调同一脚本的准备/启动阶段，不递归开启另一套相机。
不要手工设置该内部变量绕过采集启动器。

## 每条示范

1. 录制外布置：抽屉关闭、方块处于本条预定位置，两臂处于已验收的任务起始状态。
2. 确认两个 ALIGNED、反馈/相机/VR 都新鲜，HUD 为 READY。
3. 单按并松开 X。等 REC RECORDING 再动，不在 STARTING 阶段抢先做任务。
4. 连贯完成“左手打开抽屉，右手取方块、放入、释放并离开”。
5. 保留短暂、清楚可见的稳定成功末态，再单按 X。
6. 保持不动，等 IDLE / Saved: success。若尾帧/四路关节流不完整，结果可能降为 fail。
7. 再在录制外复位物体和机械臂任务起始状态；不要把复位轨迹录进下一条。
8. 下一条继续 X；不必每条 B/A、回官方 home 或重新标定，除非确实停止/重启过。

本轮任务成功条件为方块完全进入抽屉、右夹爪已释放，未要求再关抽屉。
人工伸手介入、掉物、长时间反复乱试不能标为无干预成功。
先完成一条完整试采并回放，再试录少量条目；确认质量后再批量采集。

若失败但没有危险，可在电脑点击 Fail，结束数据但不关机械臂。
若要停止机械臂，按 B；先保证现场安全，再等保存结果。
危险时直接用硬件空开，不为保存文件等待网页。
B 后重新操作需 A/Start Arm、等待 STARTED、重新对齐，再录下一条。
网页退出/VR 断流、反馈过期、Arm Start/Stop 会使当前条请求失败结束；
这不是已验收的硬件失联停机联锁。

全局和双腕在相机服务入 Store 前对 720p JPEG 作一次无损系数域 180° 旋转，
不重复有损编码；胸部保留原 JPEG。三路带 `rot180-v1`，胸部带 `identity-v1`，

转换训练数据时直接使用这些已旋转图像，不再次翻转；未来部署预处理也必须匹配。
旧数据/旧样图不被覆盖，部署推理仍未接通和验收。

## 边界与质检

开始时间随命令写入侧车，Recorder 按源时间过滤启动/对齐遗留的关节样本；
相机源时间早于开始边界的预览帧不归入 episode。
结束边界在相机桥接处理结束命令时确定，另保留请求结束的时间；
Recorder 按此边界裁掉跨输入队列超前到达的结束后关节样本。
结束后必须等待确认再复位，不能把按键时刻当成全部文件已经落盘。

成功结束需已发布四路图像的帧数屏障通过，并存在左右 obs/action 四路有效样本。
`ended:success` 在数据同步及 metadata 提交后回传；不是任务视觉成功或整机断电恢复证明。
本地 Cancel 改为保留失败，不调用上游会删除 episode 的 cancel。
原始失败先保留，训练时按 success 和后续质检结果筛选，不直接全部混入成功主集。

试录后逐条回放 JPEG，核对四路角色/方向、夹爪和动作单位、观测时间戳、
样本间隔/缺口、动作/图像事件对齐、起始与末态；检查没有启动和复位段。
相机侧车与 JPEG 时间戳集合要一致，四个 Parquet 都要非空。
没有做曝光同步或端到端时延标定，不按“第 N 帧”硬拼四路。
异常退出可能只留下部分数据，不能因为目录存在就判定成功。
1 秒新鲜门控检查的是驱动状态包/源时间，不保证每个电机底层回包均完整、新鲜或已执行；
ALIGNED 也是上游对齐标志，不是碰撞、力矩、温度或工作空间安全证明。
