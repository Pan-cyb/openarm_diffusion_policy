4. 两侧 `ALIGNED`、页面 `READY` 后左 X 开始，等 `RECORDING` 再动；成功再 X，等 `IDLE / Saved: success` 后复位。失败用 Fail；普通 B 停臂并请求将活动条记失败。红色软件急停锁住本次会话，不是物理停稳证明。只录一条先审片，不需要启动 DP。

## 整合范围

- `local/four_camera/launch.py` 为同一份正式双臂模块写入 `wide-40mm-v1` 和生产补偿参数；手柄增量生成的 IK 目标同时送往机器人与 Recorder 的 action，obs 仍来自驱动反馈。头显移动不直接生成夹爪目标，追踪质量仍受遮挡影响。
- `local/vr_gravity.py` 和 `local/dp_pilot/motion_arm.py`：正式采集与普通 DP 使能后，有新鲜八轴反馈才发送位置包。从**第一条回位位置指令**起，每条都按本侧反馈姿态计算 J1–J7 的 `clip(g(q), -cap, cap)`，同一系数 `1.0`，无渐升。正常采集停车轨迹仍走该路径；等待输入时不凭空增加运动指令，失能后不补偿。
- 原 pedestal `Kp=[70,70,70,60,10,10,10]`，`Kd=[2.75,2.5,2,2,0.7,0.6,0.5]`。保留原检查与各轴请求上限 `[6,6,2,6,1,1,1] N·m`，不改夹爪 POS_FORCE。100% 是模型请求比例，不是最大电机力矩，也不是实测力矩。
- DP 只共用控制配置，不改示范起点、模型或权重，不使用头显；`--no-gravity` 仍是显式零前馈对照。`--gravity-trial` 和 `--fixed-replay` 继续保留各自的实验时序和停止语义，不用于正式采集。
