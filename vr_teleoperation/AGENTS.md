# Quest WebXR 遥操作规则

## 范围

- 本目录负责 Quest 3 WebXR 到 OpenArm V2 pedestal 的仿真与实机遥操作链路。
- 当前目标模型固定为普通 OpenArm 2.0 双臂加底座，不是 OpenArm Cell。
- IK 和 MuJoCo 必须使用同一个模型：
  `../openarm_v2/vendor/openarm_mujoco/v2/pedestal/pedestal.xml`。
- 正式数据采集只使用显式授权的分阶段入口；默认离线/mock，不因软件接入完成
  自动开设备。实机只使用官方 `dora-openarm` pedestal 驱动。
- WebXR immersive 是唯一当前主线。
- 原生 UDP controller-only 是暂停的实验坑位，保留实现但不作为当前验收入口。
- 开发阶段通过 ADB reverse 暴露 `http://localhost:8080`，不修改 Quest 信任区。
- WebXR 主线要求正常佩戴头显；不得把 `neck` 位姿模式解释为可以把头显挂在脖子上。

## 目录

- `upstream/` 保存固定的第三方仓库，不在父仓库提交。
- `local/` 保存本项目自己的数据流、脚本、测试和简洁文档。
- `downloads/` 保存 APK 与工具下载物，不在父仓库提交。
- `deps/` 保存可重建的用户级构建依赖，不在父仓库提交。

## 相机图像方向

- 当前两路腕部相机 `wrist_left`、`wrist_right` 和全局相机 `global` 的标准图像旋转 180 度
  （`output[y, x] = input[H - 1 - y, W - 1 - x]`），上下和左右同时反转；
  不得用仅上下翻转（`vflip`）替代，也不得额外施加镜像。
- 此约定只作用于上述三路；胸部 `chest` 不旋转，其余新增机位另行确认。
  不改变左右腕身份、机器人坐标系或动作/关节方向。
- 2026-11-20 用户确认的 bus 3 物理映射：`2.2`=右腕、`2.3`=左腕、
  `2.4`=胸部微雪、`1`=全局微雪。可读配置在
  `local/camera_bandwidth/four_camera_layout.json`；不能用重复序列号或 videoN 替代物理端口。
- 预览、数据转换/训练和部署推理必须使用一致的图像方向。每帧只应用一次；
  已变换数据应记录变换及版本，不得再次翻转，也不得覆盖既有原始数据。
- 正式采集链路是否已实现该变换，以 `docs/PROJECT_STATUS.md` 为准；
  临时旋转预览不能证明正式采集已应用。接入时需通过非对称图案确认方向，
  并记录变换实际应用的位置。

## 边界

- 不修改 `upstream/` 中的固定上游源码；适配写在 `local/`。
- 不修改 `openarm_v2/vendor/` 中的官方 V2 模型。
- 不把 Cell、V1 或真机结论作为 pedestal 主线证据。
- 仿真最小 WebXR 数据流不加载采集 UI、Recorder 或 Cell 的五路相机；
  采集派生数据流复用官方 UI/Recorder，本地适配层统一桌面和 VR 的 episode 状态。
- A 是 Arm Start，不开始录制；X 仅在双臂 ALIGNED 且输入新鲜时开始，
  再次 X 请求成功结束；B 保留优先停臂并将活动条记失败的职责。
  开始/结束都等待 Recorder 确认，不录启动、对齐与复位。
- 保存成功确认必须晚于本条数据、目录和 metadata 的持久化屏障；
  不用文件存在或已关闭代替 fsync，不把未提交的部分文件当成成功条目。
- 诊断预览应标注源时间/预热选帧，不把启动第一帧与稳定阶段混比；
  不以人工拉亮或选择最亮帧冒充曝光质量改善，保留未经修改的原始图像。
- 真实采集默认保存 Expansion UUID `b8104161-e073-d644-a4b9-f4efbcfc1463` 上的
  `openarm_datasets/drawer_block/raw`；未挂载不得自动回退系统盘。
- 8080 裸地址自动跳到内容版本路径；改前端后需重启服务并核对版本，
  不把旧 Quest 会话或桌面截图当成头显验收。
- 本地 HTTP 包装器只替换 Web 服务传输层，不复制或修改上游姿态处理逻辑。
- 头显坐标轴显示原始 WebXR 手柄 aim frame；MuJoCo 坐标轴显示机器人映射后的目标 frame。
- 不得把 IK 有输出解释为目标可达；必须另行检查 FK 残差、关节裕量、奇异位形和碰撞。
- 未明确恢复 UDP 路线前，不继续测试挂脖子用法或把 UDP 作为采集主线。
- 未经新的明确授权，不打开 CAN/串口或发送真机运动命令。
- 实机启动不得设置为开机自启；必须现场输入 `START` 运动确认词。
- 单条 CAN 总线同时只能有一个控制或诊断进程，不并行运行 `monitor`、
  `diagnose`、参数读取或自定义控制脚本。
- 不再使用自定义底层 MIT 运动脚本做实机关节试验；实机轨迹使用官方
  `openarm_driver` 或官方 Dora 数据流的安全检查与限速。
- VR B/A/X 控制和录制门控在完成实机验收前不得替代电脑 UI 和硬件空开。
- 主机卡死/异常重启后，先只读核对进程、接口和落盘完整性，再决定是否恢复负载；
  不删除不完整诊断文件、不以重新采样覆盖失败证据，也不自动运行磁盘修复或硬件压力测试。
